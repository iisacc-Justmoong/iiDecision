# 의사결정 모델 계약

## 상태와 선택지

`DecisionModel::create`는 선택지별 고유 ID, 표시 이름, 가중치 벡터, 편향과 양수
temperature를 받는다. 모든 선택지는 같은 특징 개수를 사용한다. 표시 이름은
비어도 되지만 ID는 비어 있거나 중복될 수 없다. 특징이 없는 모델은 편향만 사용한다.

`predict`는 동일한 순서와 단위의 수치 특징을 받는다. 특징 추출·정규화는 소비자의
책임이다. 각 선택의 logit은 `bias + sum(weight * feature)`이며, 확률은 최대 logit을
뺀 다음 temperature로 나누는 안정화 softmax로 계산한다. 선택지 순서를 보존하고
동률이면 먼저 정의한 선택지를 고른다. 단일 선택의 확률과 margin은 1이다.

입력·가중치·편향에는 NaN이나 무한대를 허용하지 않는다. 특징 개수 불일치와
산술 오버플로는 `std::expected`의 `Error`로 반환한다. 확률의 정상적인 언더플로는
0으로 표현한다. 실패한 예측에는 부분 결과를 반환하지 않는다.

## 지도학습

`train`은 특징과 정답 선택 ID를 가진 예제를 고정 순서로 순회하며 categorical
cross-entropy의 stochastic gradient descent를 수행한다. epochs와 learning_rate는
호출자가 지정한다. temperature에 따른 gradient 배율도 반영한다. 학습 결과는
업데이트 수와 최종 데이터셋의 평균 negative log-likelihood이다. 손실 계산에서는
0 확률의 로그를 피하기 위해 최소 양의 정규 double 값으로만 확률을 제한한다.

학습은 파라미터 사본에서 수행한다. 잘못된 예제, 알 수 없는 선택 ID, 학습 옵션
오류 또는 수치 오버플로가 발생하면 원본 모델을 유지한다. 전체 학습과 최종 손실
계산이 성공한 경우에만 파라미터를 교체한다.

모델 사본은 독립적인 파라미터를 소유한다. 입력과 파라미터가 같으면 예측은
동일하며 난수를 사용하지 않는다. 동시 읽기는 가능하지만 학습과 읽기를 같은
인스턴스에서 동시에 수행하려면 소비자가 동기화해야 한다.

## LLM 앞단에서의 역할

호출자는 전체 확률 분포와 margin으로 이미 알려진 작업의 분기를 결정하거나,
불확실한 결과에 더 많은 추론이 필요한지 판단할 수 있다. 선택지 자체와 LLM 호출
정책을 모델 내부에 숨기지 않는다. 데이터 수집, 특징 추출, 모델 학습·평가와 실제
업무 실행은 서로 다른 책임이다.

이 초기 모델은 정의된 특징과 학습 데이터 범위에서 동작한다. 범용 자연어 판단,
사전학습 언어 인코더, 모델 파일 형식, 확률 보정 및 GPU 실행은 아직 제공하지 않는다.
보정되지 않은 softmax 확률을 실제 정답률로 주장하지 않는다.

설계 참고: [TypeSafe Jev 소개](https://docs.typesafe.ai/introduction)는 상태와 정해진
질문에서 구조화된 선택과 확률을 반환하는 역할을 설명한다. iiDecision은 해당
API나 구현의 복제본이 아니며 원격 Jev 서비스를 호출하지 않는다.
